## Tier 1 — common-config blockers

The fixtures we'd love to drop in unmodified (Debian default,
Arch default, real `nftables.conf`s shared in the wild) all fail
on these. Each is a small per-construct addition: one or two
clauses in the parser + compiler + formatter + a fixture.

- 🔴 **`limit rate N/period [burst N]`** — no `Expr.limit`
  constructor on the Linx side. Needs the `%Expr{}` shape + wire
  encoder + compiler emit + formatter inverse. The parser already
  accepts `limit rate N/second` and returns a clean ParseError
  pointing at the gap.
- 🔴 **`meta FIELD set VALUE` / `ct FIELD set VALUE`** — no
  setter `%Expr{}` yet. Parser accepts the syntax and the
  compiler raises a precise ParseError. Common in NAT chains
  (`meta mark set 0xN`) and conntrack mangling (`ct mark set
  meta mark`).
- 🔴 **Named objects at table level** — `counter ctr { }`,
  `quota q { over 10 mbytes }`, `limit l { rate 100/sec }`.
  Parser accepts; compiler raises. Needs per-kind `%Object{}`
  data-shape + wire codec + `Ruleset.add_object!` polish.
- 🔴 **Flowtables (declarative side)** —
  `flowtable ft { hook ingress priority filter; devices = { eth0 } }`.
  Parser accepts; compiler raises. Needs the `%Flowtable{}` codec
  + `Ruleset.add_flowtable!` polish.
- 🔴 **Concatenated set/map keys** — `type ipv4_addr .
  inet_service`. Parser accepts as `{:concat, [...]}`; compiler
  raises. Needs Set/Map key-type validation + wire-encoding for
  concatenated keys (the kube-proxy NAT pattern).
- 🔴 **`snat ip6 prefix to ADDR`** — NPTv6 (network prefix
  translation). Niche but specific — the home-router fixture
  has a commented-out version. Single grammar variant in NAT
  statement; parser case + compiler case.
- 🔴 **`include "path"` substitution** — currently parses and
  the compiler ignores it. Real configs split into multiple
  files; we need to actually read and inline the included file.
  Defines and include directives compose (a defined macro might
  be referenced in an included file).
- 🔴 **`define name = value` substitution** — same story.
  Parser captures `{:define, name, value, meta}`; compiler
  doesn't yet apply substitution at use sites.

## Tier 2 — sigil ergonomics / polish

The ~NFT story works end-to-end but has rough edges worth
smoothing:

- 🟡 **AST-aware sigil reflow** — `mix format` currently
  passes interpolation-bearing `~NFT` bodies through unchanged.
  An AST-to-source emitter (parallel to the existing
  Expr-to-source one) would let us reflow the surrounding nft
  syntax while preserving `#{...}` positions verbatim. ~400
  LOC.
- 🟡 **Interpolation in keyword positions** — currently only
  match-RHS positions accept `#{...}`. Table names, chain names,
  family atoms, hook atoms, etc. would each need their own
  RuntimeCompiler dispatch + Runtime helper. ~50 LOC per
  position kind.
- 🟡 **ICMPv4 symbolic names** — `echo-request` etc. currently
  resolve to their ICMPv6 values (128, …). ICMPv4 has different
  values (`echo-request` = 8). Would need family-context
  threaded through compile_rhs OR a separate
  `icmpv4_type_int/1` table with explicit dispatch on the
  `:icmp` vs `:icmpv6` payload alias.
- 🟡 **More bare meta shorthands** — currently `iifname` /
  `oifname` / `iif` / `oif`. nft also accepts bare `mark` /
  `priority` / `protocol` / `nfproto` / `l4proto` /
  `length`. Each is one extra entry in `@bare_meta_fields`,
  but `mark` specifically is ambiguous with the `mark set` setter
  — needs a small lookahead.

## Tier 4 — long-tail expressions

Each of these is "one new expression kind" — tokenizer keyword
(maybe), parser dispatch, compiler dispatch, wire-codec dispatch,
formatter inverse. Shipped per-demand when a use case appears.

- 🔵 **`synproxy`** — SYN-proxy expression for DDoS protection.
- 🔵 **`secmark`** — SELinux/AppArmor packet labelling.
- 🔵 **`osf`** — passive OS fingerprinting.
- 🔵 **`fib`** — forwarding-info-base lookups
  (`fib saddr oif`).
- 🔵 **`jhash` / `hash` symmetric** — hash-based selection for
  load balancing.
- 🔵 **`numgen`** — round-robin / random number generator
  expressions.
- 🔵 **`xfrm`** — IPsec policy matching (`xfrm in spi`,
  `xfrm req`).
- 🔵 **`tunnel`** — tunnel-metadata matches (vxlan, geneve, …).
- 🔵 **`dup` / `fwd`** — packet duplication / forwarding to
  another interface (netdev family).
- 🔵 **`xt` compat shims** — `xt match "tcp_mss"` etc. for
  iptables-translate-style configs. Out of scope unless someone
  actively migrates from iptables.
- 🔵 **Raw payload syntax** — `@th,0,16` for "transport header,
  offset 0, 16 bits." Already supported in our Expr.payload/3
  but not exposed in the ~NFT parser.
- 🔵 **Advanced ct fields** — `ct direction`, `ct mark`,
  `ct label`, `ct status`, `ct helper`, `ct expiration`,
  `ct count`, `ct zone`, `ct id`, `ct l3proto`, `ct
  protocol`, `ct bytes`, `ct packets`.
- 🔵 **Conntrack helpers / zones / timeouts as named objects**
  (`ct helper h { … }`, `ct timeout t { … }`, `ct expectation
  e { … }`). Companion to the named-objects Tier 1 item.

## Tier 5 — deferred subsystems

Substantial work, not on the v1.5 ship list but architected for.

- ⏳ **`Linx.Netfilter.Queue` (NFQUEUE)** — userspace verdict
  proxy via `NFNL_SUBSYS_QUEUE`. Needs careful backpressure
  design; no driving use case surfaced.
- ⏳ **`Linx.Netfilter.Conntrack` event stream** —
  `NFNLGRP_CONNTRACK_NEW/UPDATE/DESTROY` broadcast subscription.
  Natural fit for "live connections" LiveView panels.
- ⏳ **`Linx.Netfilter.Conntrack` write side** — `conntrack -D`
  / `-U` equivalents (force-delete an entry, update mark/label/
  timeout). Useful for "flush conntrack after NAT rule change so
  flows pick up the new mapping."
- ⏳ **Hook introspection** (`NFNL_SUBSYS_HOOK`, 5.16+) — "who
  else has rules at this hook + priority?" Coexistence audit
  tool.
- ⏳ **Trivia-preserving Conf parser** — preserve `#` comments,
  `define` names, blank lines, original ordering on emit. ~30%
  extra parser complexity; ship when a `nft-format`-style tool
  driver appears.
- ⏳ **JSON form (`nft -j`) adapter** — bridge Linx's value
  type to libnftables's JSON schema. Genuinely external
  (consumer-side adapter); only build when an interop need
  arises.
